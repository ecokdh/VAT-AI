# 이메일 인증 코드로 비밀번호 재설정

기존 비밀번호 찾기 화면의 스타일을 사용한다. 흐름은 이메일 입력 → 6자리 코드 확인 → 새 비밀번호 입력 → 로그인이다.

발송 메일은 `app/auth/templates/password_reset.html`의 VAT-AI 편지형 HTML을 사용한다. 인증 코드를 강조한 카드·안내·서명으로 구성하며, 외부 이미지나 추적 리소스를 사용하지 않는다. HTML 미지원 메일 앱을 위해 같은 코드의 일반 텍스트 본문을 `multipart/alternative`로 함께 보낸다.

- 가입된 이메일만 메일을 발송한다. 미가입 이메일은 `404 EMAIL_NOT_REGISTERED`로 안내한다. 가입 여부를 의도적으로 표시하는 정책이다.
- 코드는 10분간 유효하며 5회까지 확인할 수 있다. 확인 성공 후 코드는 재사용할 수 없다.
- 재발송 간격은 60초, 이메일당 시간당 최대 3회, 요청 IP당 시간당 최대 20회다.
- 60초 대기 중 유효한 미인증 요청이 있으면 메일을 또 보내지 않고 기존 코드 입력 단계로 연결한다.
- 같은 탭에서 새로고침하거나 메일 확인 후 돌아와도 만료 전 코드 입력 단계를 복원한다. 세션 저장소에는 이메일·요청 ID·만료 시각만 보관하며 코드·비밀번호·인증 후 토큰은 저장하지 않는다.
- 재발송 성공 시 이전 코드와 재설정 토큰을 만료시킨다. 발송 실패는 성공으로 표시하지 않는다.
- 코드는 서버 비밀키로 HMAC 처리해 저장하며, API 응답·로그에 포함하지 않는다.
- 코드 확인에 성공하면 10분 유효한 일회용 토큰을 발급한다. 프론트엔드는 토큰을 메모리에만 보관한다.
- 새 비밀번호는 영문·숫자·특수문자를 포함한 8자 이상, UTF-8 72바이트 이하다. 변경 시 기존 로그인과 모든 재설정 요청을 무효화한다.

## 발송 설정

서버의 `.env` 또는 우선순위가 더 높은 `.env.luna.local`에 실제 SMTP 제공업체의 값을 설정한다. 비밀 값은 Git에 커밋하지 않는다.

```dotenv
SMTP_HOST=제공업체의_SMTP_호스트
SMTP_PORT=587
SMTP_USE_SSL=false
SMTP_USERNAME=SMTP_사용자명
SMTP_PASSWORD=SMTP_인증정보
SMTP_FROM=발신자_이메일
```

587 포트는 STARTTLS를 사용한다. 제공업체에서 465 포트의 SSL 연결을 요구하면 `SMTP_PORT=465`, `SMTP_USE_SSL=true`로 설정한다. 발신 주소는 제공업체에서 사용을 허용한 주소여야 한다.

설정 변경 뒤 API 프로세스를 다시 시작한다. 설정이 비어 있으면 가입된 주소 요청에 `503 EMAIL_NOT_CONFIGURED`, SMTP 발송 실패 시 `503 EMAIL_DELIVERY_FAILED`를 반환한다. 실제 메일 도착은 SMTP 설정과 수신함 확인까지 별도로 검증해야 한다.

## 스키마와 API

기존 DB를 백업한 뒤 `python -m alembic upgrade head`를 실행한다. `e51b60aa0017`은 기존 재설정 테이블에 코드 해시, 오입력 횟수, 인증 완료 시각을 추가한다.

1. `POST /auth/forgot-password`: `{ "email": "..." }` → `request_id`, `expires_in`, `retry_after`, `message`
2. `POST /auth/verify-reset-code`: `{ "request_id": "...", "code": "012345" }` → `token`, `message`
3. `POST /auth/reset-password`: `{ "token": "...", "password": "..." }` → `message`

코드를 입력할 때 이메일을 다시 받지 않으며, 서버가 최초 요청의 사용자에게 토큰을 연결한다. 이전에 발급된 링크의 토큰은 만료 전까지 기존 재설정 API에서 사용할 수 있다.
