# 로컬 QA 개선 공유

OCR에서 선택한 매입·매출 구분이 보관함까지 유지되도록 연결하고, 거래 저장 후 홈으로 이동하던 흐름과 매출 복원 후 매입 보관함이 표시되던 문제를 수정했습니다. 삭제 전 확인창을 추가했습니다.

Notion 신버전 디자인을 기준으로 홈·메뉴·두 보관함·신고 전 검토를 정리했습니다. 보관함의 기간·월·상태 필터를 실제 목록과 연결하고, OCR 추출 여부와 누락 항목을 표시합니다. OCR 확인·저장만으로 금액이 집계되지 않으며 거래 확정과 매입 공제 분석 단계를 거쳐 반영되는 정책을 회귀 테스트로 확인했습니다.

## 변경 내용

- 하단 OCR / 홈 / 보관함 탐색, 계정 메뉴 및 비밀번호 보기 기능 추가.
- OCR 전 매입·매출 선택, 로딩 및 추출 확인 화면의 원본 이미지 미리보기 제공.
- 추출 확인 버튼을 ‘확인 후 보관함으로 이동’으로 통일하고 해당 보관함으로 연결.
- 매입·매출 보관함 UI 통합 및 날짜·금액 정렬 제공.
- 선택 거래의 분석 로딩, 가능 / 애매 / 불가능 결과, 메모 및 더보기 표시.
- 애매 결과의 상세 패널과 서버가 제공한 근거 표시.
- 거래 삭제 확인창, 매출 거래 복원 후 매출 보관함 이동 지원.
- 증빙 방향 저장 마이그레이션, 소유권을 확인하는 원본 이미지 API 및 회귀 테스트 추가.
- 홈에 실제 신고 준비 건수·예상세액·확인 항목 표시, 이동 시 선택 기간 유지.
- 보관함 공통 카드 UI, 전체·1~12월 및 상태 필터, 큰 분석·추가 버튼, 맨 위로 이동 제공.
- OCR 필수항목별 추출 상태와 누락 개수·항목명 표시. 미확정 수기 거래는 분석보다 거래 확인을 먼저 안내.
- 마이페이지에서 프로필 사진 및 사업자 설정 제공. 2차 항목별 판정과 화면은 [ROUND2_QA.md](ROUND2_QA.md) 참고.

## 적용 시 확인

- API 및 worker 실행 전 `python -m alembic upgrade head` 적용 필요.
- 로컬 QA는 SQLite 기준. PostgreSQL 실행 검증은 별도 필요.
- 실제 OCR 정확도는 CLOVA 설정 후 추가 검증 필요.
- 공제 분석 어댑터가 없으면 기본 분석기는 검토 보류로 처리. 실제 판정 및 법령·판례 정확도는 별도 검증 필요.
- `.env`, 로컬 DB, 업로드 원본 및 설치 폴더는 공유 대상에서 제외.
- 재현 방법과 화면 캡처는 [LOCAL_QA.md](LOCAL_QA.md) 참고.
- 사업자 설정은 단일 접이식 폼으로, 목표 디자인의 세 구역 분리는 보완 필요. 프로필 사진은 현재 브라우저에만 저장.
- 우측 로딩 아이콘은 보류. 신고 기간은 2026년 범위. 이번 2차 브라우저 QA에서 PDF 다운로드는 재검증하지 않음.
